# أكاديمية الإمام لتحفيظ القرآن الكريم — بالقرآن نحيا

إصدار **6.2.0** من نظام أكاديمية الإمام لتحفيظ القرآن الكريم — «بالقرآن نحيا».

التطبيق **PWA محلي أولاً (Local‑First)**: يعمل من المتصفح، قابل للتثبيت على الهاتف أو الكمبيوتر، ويستمر في العمل دون إنترنت بعد أول تحميل ناجح. لا يحتاج خادماً خلفياً ولا Firebase ولا أي مكتبات JavaScript خارجية.

## أهم الوظائف

- إدارة الطلاب وبيانات أولياء الأمور.
- جدول أسبوعي لكل طالب: الأيام، الساعة، ومدة الحصة.
- اكتشاف تعارضات المواعيد قبل الحفظ، وفحصها من صفحة الإعدادات.
- لوحة «متابعة اليوم» مرتبة حسب موعد الحصة.
- تسجيل الحضور: حضر / غاب / إجازة.
- سجل واحد للطالب في اليوم لمنع ازدواج الحضور والحصة.
- إدارة الحصة: تقييم تسميع الحصة السابقة، الحفظ الجديد، المراجعة القريبة والبعيدة، ومراجعة الأجزاء والسور.
- حفظ تلقائي لمسودة الحصة واستعادتها عند الرجوع.
- حساب الآيات الفريدة بدون تضخيم النتيجة عند تداخل النطاقات.
- فصل «الآيات المُكلَّف بها» عن «الآيات التي تم تسميعها وتقييمها».
- تقارير شهرية ورسوم بيانية محلية بدون Chart.js.
- رسائل واتساب فردية وجماعية وتقارير شهرية.
- شهادة تقدير قابلة للطباعة أو الحفظ PDF.
- نسخ احتياطي JSON بإصدار Schema وفحص آمن قبل الاستيراد.
- فحص سلامة البيانات من الإعدادات.
- مظهر فاتح/داكن وأحجام خط متعددة.
- Service Worker وتحديث داخل التطبيق عند نشر إصدار جديد.


## أبرز إضافات v6.2

- حقل سورة ذكي قابل للكتابة والاختيار من قائمة مقترحات، مع اقتراح اسم السورة تلقائياً من آخر موضع للطالب.
- تسجيل **التسميع الفعلي** للحصة السابقة، بما في ذلك حالة أن يسمّع الطالب أكثر من المقدار المطلوب؛ ويُحتسب التقدم من النطاق الذي سُمّع فعلياً.
- اختيار متعدد للسور الكاملة بالمربعات، مع بحث سريع وتحديد سور جزء عم دفعة واحدة.
- رسائل واتساب جماعية لجميع أولياء الأمور أو مجموعة مختارة، مع قوالب جاهزة للتغيير في المواعيد والإجازات والتهنئة والإعلانات والتذكيرات.
- متغيرات جديدة للرسائل: `{{نسبة_الحفظ}}` و`{{نسبة_الإنجاز}}`، مع ظهور النسب تلقائياً في رسالة المتابعة الافتراضية.
- إظهار مستوى الحفظ ونسبة الإنجاز الموثق في ملف الطالب.
- هوية بصرية جديدة لأكاديمية الإمام وأيقونات PWA جديدة باللون الأخضر والذهبي.

## ما تغيّر في v6.2

تمت إعادة بناء الأجزاء الحساسة في التطبيق بدلاً من إضافة واجهات فوق البنية القديمة فقط. من أهم الإصلاحات:

1. توحيد سجل الحضور والحصة لنفس الطالب واليوم، مع Upsert بدلاً من إنشاء سجلات مكررة.
2. تصحيح دلالة التقييم: `prevGrades` هو تقييم ما تم تسميعه فعلياً، بينما التكليف الحالي يظل للحصة التالية.
3. دمج نطاقات الآيات المتداخلة عند الحساب، مثل 1–10 ثم 5–15 = 15 آية لا 21.
4. حساب التقدم الموثق من المقاطع التي تم تسميعها وتقييمها، وإظهار التكليفات كمقياس مستقل.
5. تصحيح الغياب والإجازة ونسبة الحضور والـ Streak.
6. إصلاح الطباعة للتقارير والشهادات.
7. إزالة Dexie وChart.js وكل اعتماد CDN؛ التخزين والرسوم أصبحت Native بالكامل.
8. IndexedDB أصلي مع نسخة أمان في localStorage وتوافق مع قاعدة `QuranApp` القديمة.
9. إصلاح Service Worker، الأيقونات، Maskable Icon، وتدفق تحديث الـPWA.
10. Autosave لمسودات الحصص، والتحقق من ملفات النسخ الاحتياطية قبل الاستيراد.
11. إضافة الجدول الأسبوعي واكتشاف التعارضات.
12. تحسينات أمنية لمنع إدخال IDs غير آمنة من ملفات النسخ الاحتياطية.

راجع [CHANGELOG.md](CHANGELOG.md) للتفاصيل.

## التشغيل محلياً

لا توجد خطوة Build.

يمكن فتح المشروع عبر أي Web Server محلي. مثال:

```bash
python3 -m http.server 8080
```

ثم افتح:

```text
http://localhost:8080
```

> لا يُنصح بفتح `index.html` مباشرة بصيغة `file://` لأن Service Worker وميزات PWA تحتاج HTTP/HTTPS.

## النشر على GitHub Pages

المشروع جاهز للنشر من جذر المستودع. توجد بالفعل `CNAME` للدومين:

```text
welivequran.online
```

الطريقة المختصرة:

1. أنشئ Repository جديداً أو استخدم المستودع الحالي.
2. ارفع **محتويات هذا المجلد نفسها** إلى جذر فرع `main`.
3. من GitHub افتح **Settings → Pages**.
4. اختر **Deploy from a branch** ثم `main` و`/(root)`.
5. انتظر اكتمال النشر وتأكد من تفعيل HTTPS.

تفاصيل إضافية في [DEPLOYMENT.md](DEPLOYMENT.md).

## البيانات والخصوصية

- الطلاب والحصص مخزنة محلياً في IndexedDB على الجهاز.
- توجد نسخة أمان محلية في localStorage لتقليل خطر فقد البيانات في حالات فشل IndexedDB.
- لا تُرسل بيانات الطلاب إلى خادم من التطبيق نفسه.
- فتح واتساب يتم فقط عند ضغط المستخدم على زر الإرسال.
- يجب تصدير نسخة احتياطية دورياً، خصوصاً قبل مسح بيانات المتصفح أو تغيير الجهاز.

### الانتقال من النسخة القديمة

عند نشر v6 على **نفس الدومين** وفتحها في **نفس المتصفح/الجهاز**، يحاول التطبيق قراءة قاعدة `QuranApp` الحالية وترقية البيانات إلى Schema 6 تلقائياً. مع ذلك، يوصى دائماً بأخذ نسخة احتياطية من الإصدار القديم قبل الاستبدال.

## الإشعارات

الإشعار الحالي هو **تذكير عند استخدام/فتح التطبيق** إذا لم تكتمل متابعة الطلاب المجدولين لذلك اليوم. لا يدّعي التطبيق وجود جدولة Push حقيقية أثناء إغلاقه؛ ذلك يحتاج خدمة Push وخادماً خلفياً، وهو خارج نطاق النسخة المحلية v6.

## بنية المشروع

```text
.
├── index.html            واجهة التطبيق
├── styles.css            جميع الأنماط
├── app.js                منطق التطبيق والتخزين والتقارير
├── sw.js                 Service Worker
├── manifest.json         تعريف PWA
├── icon-*.png            أيقونات التطبيق
├── favicon.png
├── CNAME                 الدومين المخصص لـ GitHub Pages
├── tests/
│   └── smoke.test.js     اختبارات منطق أساسية بدون dependencies
└── .github/workflows/
    └── quality.yml       فحص Syntax وتشغيل الاختبارات على GitHub
```

## الاختبارات

إذا كان Node.js مثبتاً:

```bash
npm test
```

أو مباشرة:

```bash
node tests/smoke.test.js
```

الاختبارات تغطي منطقاً حساساً مثل دمج نطاقات الآيات، الـStreak، تعارضات الجدول، ومتوسطات التقييم.

## حدود الإصدار الحالي

- المزامنة بين عدة أجهزة غير مفعلة في v6؛ المصدر الأساسي للبيانات هو الجهاز الحالي.
- لا توجد حسابات مستخدمين أو Cloud Sync.
- الإشعارات الخلفية الحقيقية تحتاج Backend/Push service.

هذه الحدود مقصودة في v6 للحفاظ على الاعتمادية، العمل دون إنترنت، وعدم تعريض بيانات الطلاب لخدمة خارجية قبل بناء مزامنة مؤمنة بصورة صحيحة.
