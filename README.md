## v10.1.4 — Safe Multi-Device Sync

- حذف الطالب/المهمة يُسجّل Tombstone دائمًا حتى لا تعود البيانات المحذوفة من جهاز آخر.
- حذف الطالب يشمل Tombstones للحصص والمهام التابعة له.
- كل جهاز يحصل على `deviceId` محلي مستقل، والسجلات تحمل `updatedByDevice` مع `updatedAt`.
- المزامنة أصبحت Pull → Merge → Push، وليس Push مباشرًا.
- جدول `account_sync` يحمل `revision`، والرفع يستخدم Compare-And-Swap لمنع جهاز قديم من الكتابة فوق Snapshot أحدث.
- عند تعارض Revision يعيد العميل التنزيل والدمج ثم يحاول الرفع مرة أخرى تلقائيًا.
- ترقية أي إعداد مزامنة قديم إلى البروتوكول الآمن توقف Auto Sync مرة واحدة حتى يختبر المستخدم الإصدار الجديد.
- Schema ما زال 12؛ لا يوجد تغيير في بنية الطلاب أو الحصص.

## v10.1.2 — Google Login & Access Control

- تسجيل الدخول عبر Google باستخدام Supabase Auth.
- الحساب `info.welivequran@gmail.com` يصبح **Owner نشطًا** تلقائيًا بعد تنفيذ SQL وأول تسجيل دخول.
- أي حساب Google جديد يصبح **Pending** ولا يدخل التطبيق حتى يفعّله الـOwner.
- الـOwner يستطيع تفعيل/إيقاف المستخدمين من بطاقة «صلاحيات الدخول» داخل الإعدادات.
- الجهاز الذي تم التحقق منه مرة واحدة يمكنه فتح البيانات المحلية Offline؛ عند عودة الإنترنت تتم إعادة مراجعة حالة الحساب.
- Cloud Sync أصبح يتطلب جلسة مستخدم Authenticated إضافة إلى Sync ID/Authorization Secret والتشفير المحلي.
- إضافة `privacy.html` و`terms.html` لاستخدامهما مع Google OAuth Branding.
- لا يوجد Schema Migration لبيانات التطبيق؛ ما زال Schema 12.

> **إعداد Supabase لأول مرة:** نفّذ `sql/supabase-setup.sql` كاملًا من SQL Editor قبل اختبار تسجيل الدخول. لا تستخدم أو تشارك أي Secret/Service Role key في كود الواجهة.

## v10.1.1 — Security & Stabilization


- Portable Backup لا يصدّر PIN أو WebAuthn credential أو مفاتيح/كلمات/أسرار المزامنة.
